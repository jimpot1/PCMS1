## 1️⃣ QUANTITY ANOMALY

### ⭐ AI Support: ✅ YES

### What It Detects
When a **stock movement quantity is statistically unusual** for a specific supply in a specific department.

### Real-World Example

```
Scenario: Ballpen Stock Movement
─────────────────────────────────────
Department: Engineering
Supply: Ballpen

Historical movements: [100, 120, 110, 115, 105] units
Average: 110 units
Standard Deviation: 7.9 units

TODAY'S MOVEMENT: 250 units ❌ ANOMALY DETECTED!
```

### How It's Calculated: Z-Score Analysis

**Mathematical Formula:**
```
Z-Score = (Current Value - Average) / Standard Deviation
Z-Score = (250 - 110) / 7.9
Z-Score = 17.7
```

**Interpretation:**
- Z-score = **17.7** means the value is **17.7 standard deviations** away from normal
- Normal range: **-2 to +2** standard deviations
- Anything **> 2 is flagged as anomalous** (statistically in the top 5%)
- Z = 17.7 is **EXTREMELY unusual** ⚠️

**Visual Representation:**
```
        Statistical Distribution
        
        -3σ  -2σ  -1σ   Mean  +1σ  +2σ  +3σ .... +17.7σ
         |    |    |     |     |    |    |        |
    ◄────┴────┴────┴─────●────┴────┴────┴────────╳
    NORMAL RANGE         110              ANOMALY
    (95% of data)                         250 units
```

### Why It Matters
- **Could indicate:**
  - Special project or event
  - Department expansion
  - Wastage or mismanagement
  - Potential fraud or theft
  - Inventory discrepancy

- **Needs investigation:** Why did they request 250 when they normally request ~110?

### When It's Created
- During stock movement processing
- When a department requests supplies
- When stock adjustments are made
- Real-time detection during workflow

### Alert Priority
- **Risk Score:** 6.0 (Medium)
- **Priority Level:** MEDIUM - Requires investigation within 24-48 hours

### AI Explanation: ✅ YES

**Groq LLM analyzes:**
- How unusual is this really? (statistical probability)
- What could cause such a spike?
- Is this a legitimate need or potential fraud?
- What should the OIC verify?
- What are the risk implications?

**Example AI Response:**
```
"The ballpen request spiked to 250 units, well above the historical 
average of 110 (z-score: 17.7). This represents a significant 127% 
increase from normal demand. 

Possible causes:
• New training program requiring supplies
• Facility expansion or relocation
• Special promotional event
• Inventory correction from prior shortage

Recommendation: OIC should verify this request aligns with a known 
department initiative. Monitor for similar spikes to detect patterns 
of unusual behavior or potential wastage."
```

### Database Fields
```sql
- source_type: 'quantity_anomaly'
- source_id: department_id
- current_quantity: 250
- historical_average: 110
- historical_stddev: 7.9
- z_score: 17.7
- historical_quantities: [100, 120, 110, 115, 105]
- analysis_context: JSON with full statistical data
- ai_explanation: Generated by Groq
- ai_explanation_status: 'pending' | 'generated' | 'failed'
```

## 2️⃣ REQUESTER FREQUENCY ANOMALY

### ⭐ AI Support: ✅ YES (NEW FEATURE)

### What It Detects
When a **single person requests supplies too often** in a short time period compared to their normal historical behavior.

### Real-World Example

```
Scenario: John Doe's Ballpen Requests
─────────────────────────────────────────
Requester: John Doe (Engineering Department)
Supply: Ballpen
Time Analysis: Last 6 months

Month 1: 2 requests
Month 2: 3 requests  
Month 3: 1 request
Month 4: 2 requests
Month 5: 2 requests
Month 6: 1 request
─────────────────
Average: 1.8 requests/month (~2 per month) ✓ NORMAL

RECENT 30 DAYS: 8 requests ❌ ANOMALY DETECTED!
```

### How It's Calculated: Frequency Z-Score

**Mathematical Formula:**
```
Recent Requests (30 days):        8 requests
Historical Average (6 months):    2 requests/month
Standard Deviation:               1.4

Z-Score = (8 - 2) / 1.4
Z-Score = 4.3
```

**Interpretation:**
- Z-score = **4.3** (well above threshold of 2)
- Current frequency is **4.3 standard deviations** above normal
- **EXTREMELY unusual behavior** ⚠️
- Request frequency increased **4x in 30 days**

**Time Window Analysis:**
```
6-Month Historical Baseline:          Recent 30-Day Window:
─────────────────────────────         ─────────────────────────
Month 1: 2 requests                   Week 1: 2 requests
Month 2: 3 requests                   Week 2: 2 requests
Month 3: 1 request                    Week 3: 2 requests
Month 4: 2 requests                   Week 4: 2 requests
Month 5: 2 requests                   ─────────────────
Month 6: 1 request                    TOTAL: 8 requests
──────────                            
AVG: 1.8/month                        (4x normal rate!)
```

### Why It Matters
- **Could indicate:**
  - New project requiring high supply consumption
  - Employee training/onboarding (learning curve)
  - Department reorganization or restructuring
  - Temporary increased workload
  - **FRAUD/THEFT** (selling supplies, hoarding)
  - Wastage or mismanagement

- **Needs investigation:** Is there a legitimate reason for 8 requests in 30 days?

### When It's Created
- During purchase request submission
- When system detects unusual frequency pattern
- Can be triggered manually by administrators
- Real-time detection during workflow

### Alert Priority
- **Risk Score:** 5.0 (Medium)
- **Priority Level:** MEDIUM - Requires review within 24-48 hours
- **Notifications sent to:** Property Custodian, PPMO Staff, System Administrators

### AI Explanation: ✅ YES

**Groq LLM analyzes:**
- Is this frequency truly unusual? (statistical significance)
- What could legitimately cause increased requests?
- Are there fraud indicators present?
- What verification steps are recommended?
- What's the risk profile?

**Example AI Response:**
```
"John Doe submitted 8 ballpen requests in the last 30 days, compared 
to his average of 2 per month. This represents a 4x increase and is 
statistically unusual (z-score: 4.3).

Possible legitimate reasons:
• New project launch requiring supplies
• Training program or staff onboarding
• Department restructuring or expansion
• Covering for absent colleague

Potential risk indicators to verify:
• Destination department (same vs. multiple)
• Quantity consistency with actual usage
• Approval status of all requests
• Supply receipt documentation

Recommendation: (1) Confirm any known department initiatives, 
(2) Review supply destination records, (3) Verify quantities align 
with stated needs, (4) Check approval history for anomalies."
```

### Database Fields
```sql
- source_type: 'requester_frequency_anomaly'
- source_id: requester_id (UUID)
- requester_id: UUID (John Doe's user ID)
- supply_id: bigint (Ballpen ID)
- department_id: bigint (Engineering ID)
- request_count: 8
- request_frequency_context: JSON with frequency data
- analysis_context: JSON with statistical analysis
- ai_explanation: Generated by Groq
- ai_explanation_status: 'pending' | 'generated' | 'failed'
```

### Request Count Context Example
```json

  "requester_id": "uuid-12345",
  "requester_name": "John Doe",
  "supply_id": 42,
  "supply_name": "Ballpen",
```

## 3️⃣ UNTRACKED TRANSFER

### ⚠️ AI Support: ❌ NO

### What It Detects
When a **physical asset is found in a different department than where it's recorded** in the system.

### Real-World Example

```
Scenario: Missing Laptop During Audit
──────────────────────────────────────────
Asset: Dell Laptop XPS 15
Serial Number: XYZ123ABC
Property Number: ABC-2024-001

System Records:
├─ Current Department: Finance
├─ Custodian: Maria (Finance Manager)
├─ Location: Finance Building, Room 205
├─ Last Update: 2026-08-15
└─ Status: In-Use

Physical Audit Results:
├─ Found at: Engineering Building, Room 412
├─ With: John (Engineering Employee)
├─ Asset Condition: Good (No damage)
└─ Status: ❌ IN WRONG LOCATION!
```

### Why It's Created
- During physical asset audit/inventory count
- When infrastructure team visually inspects assets
- During facility inspections
- When assets are physically located during operations

### Why No AI Is Needed: The Issue is Obvious

**The problem is straightforward:**
1. ✅ Asset physically exists in Department A (verified)
2. ✅ System records it in Department B (verified)
3. ❌ **Location mismatch = the anomaly itself**
4. ✅ **Action is clear:** Either fix records or recover asset

**There's nothing to "explain"** - it's a straightforward discrepancy with only two possible causes:
- **Legitimate transfer:** Records weren't updated (update them)
- **Unauthorized movement:** Asset was stolen/misplaced (recover it)

No statistical analysis or domain expertise needed.

### Alert Priority
- **Risk Score:** 7.5 (High)
- **Priority Level:** HIGH - Requires immediate investigation
- **Notifications sent to:** Property Custodian, System Administrators

### Why High Risk?
This indicates potential:
- ⚠️ Unauthorized asset movement
- 🚨 Theft or asset loss
- 📋 Compliance violation
- 🔴 Custodian accountability issue
- 📊 Poor asset tracking

### Recommended Action

**NO AI ANALYSIS - IMMEDIATE ACTION REQUIRED:**

```
Step 1: VERIFY TRANSFER LEGITIMACY
├─ Contact Department B manager/custodian
├─ Ask: "Was this asset transferred to you?"
├─ Ask: "Do you have authorization documentation?"
└─ Outcome: Legitimate or Unauthorized?

Step 2A: IF LEGITIMATE TRANSFER
├─ Verify authorization is documented
├─ Update system records:
│  ├─ New custodian: John (Engineering)
│  ├─ New department: Engineering
│  └─ New location: Building E, Room 412
├─ Update asset transfer documentation
└─ Close anomaly alert

Step 2B: IF UNAUTHORIZED
├─ Document as potential theft
├─ Report to:
│  ├─ Property Custodian
│  ├─ Security/Management
│  └─ Compliance officer
├─ Recover asset immediately
├─ Update asset status to "recovered"
└─ Document incident in activity logs

Step 3: PREVENT FUTURE OCCURRENCE
├─ Implement asset tracking process
├─ Require transfer authorization forms
├─ Schedule regular asset audits
└─ Train staff on asset handling procedures
```

### Database Fields
```sql
- source_type: 'untracked_transfer'
- source_id: asset_id
- found_department_id: department where physically found
- risk_score: 7.5
- priority: 'high'
- reason: "Asset #123 found in Dept X but recorded in Dept Y"
- recommended_action: "Review asset location and verify transfer"
- status: 'open' (until resolved)
```

## 4️⃣ LOW STOCK ALERT

### ℹ️ AI Support: ❌ NO

### What It Detects
When **inventory quantity falls below the minimum required level**.

### Real-World Example

```
Scenario 1: Ballpen Stock Alert
────────────────────────────────────
Supply: Ballpen
Minimum Stock Level: 500 units
Current Stock: 500 units

Status: ⚠️ LOW STOCK - AT MINIMUM!
Action Needed: Order supplies now


Scenario 2: Paper Stock Critical Alert
─────────────────────────────────────────
Supply: A4 Paper (Reams)
Minimum Stock Level: 100 reams
Current Stock: 45 reams

Status: 🔴 CRITICAL - VERY LOW!
Action Needed: Emergency order immediately
```

### Why It's NOT a True Anomaly

**Characteristics of a Non-Anomaly:**
- ✓ Simple threshold check: Current < Minimum? Yes/No
- ✓ NOT statistical: No complex analysis
- ✓ NOT unusual: It's an expected operational condition
- ✓ Binary condition: Either low or not low
- ✓ Solution is obvious: Buy more

**Why no AI is needed:**
- **Question AI would answer:** "Should we reorder?"
- **AI's answer:** "Yes, get more supplies."
- **Reality:** We already know the answer without AI!

### When It's Created
- Real-time stock monitoring
- Every time stock level is updated
- Continuously checked in system
- Triggered by stock movements/transfers
- Manual inventory updates

### Alert Priority
- **Risk Score:** N/A (Not an anomaly)
- **Priority Level:** OPERATIONAL - Handle within business hours
- **Urgency:** Depends on how low (critical vs. warning)

### Why Low Risk?
- ✓ **Not suspicious:** It's normal for stock to fluctuate
- ✓ **Solution obvious:** Reorder
- ✓ **No investigation:** Just process purchase order
- ✓ **No compliance issue:** Just operational management

### Recommended Action

**SIMPLE PROCUREMENT WORKFLOW:**

```
Step 1: RECOGNIZE LOW STOCK
├─ System alerts: "Ballpen stock below minimum"
└─ Status: REQUIRES ACTION

Step 2: CALCULATE REORDER QUANTITY
├─ Current stock: 45 reams
├─ Minimum required: 100 reams
├─ Safety buffer: 150 reams (1.5x minimum)
└─ Order quantity: 150 - 45 = 105 reams

Step 3: ISSUE PURCHASE ORDER
├─ Supplier: Preferred vendor
├─ Item: Ballpen (SKU: BPN-001)
├─ Quantity: 105 units
├─ Delivery: Express (3-5 days)
└─ Budget: Approved from department budget

Step 4: MONITOR DELIVERY
├─ Track shipment
├─ Verify receipt
├─ Update stock level in system
└─ Confirm alert resolved

Step 5: CLOSE ALERT
├─ Stock received: 105 units
├─ New stock level: 150 units
├─ Status: ✅ ABOVE MINIMUM
└─ Alert automatically cleared
```

### Example Scenarios

**Scenario A: Regular Low Stock**
```
Day 1:  Stock = 520 (above minimum of 500)  → ✓ OK
Day 2:  Stock = 480 (below minimum)         → ⚠️ ALERT
Day 3:  Order placed for 250 units
Day 5:  Stock = 730 after delivery          → ✓ RESOLVED
```

**Scenario B: Critical Low Stock**
```
Supply: Safety Equipment
Minimum: 100 units
Current: 5 units

Status: 🔴 EMERGENCY!
Action: Immediate order - Same day delivery if possible
Notification: Goes to Manager directly
Priority: Highest
```

### Database Fields
```sql
- source_type: 'low_stock'
- source_id: supply_id
- current_stock: 45
- minimum_stock: 100
- risk_score: NULL (not an anomaly)
- priority: 'low' or 'medium' (based on criticality)
- reason: "Ballpen stock below minimum (45/100)"
- recommended_action: "Reorder supply immediately"
- status: 'open' (until replenished)
```

## Why Some Have AI and Others Don't

### ✅ AI IS NEEDED WHEN:
1. **Multiple possible causes** - Why is demand unusual?
2. **Risk assessment required** - Is this a fraud indicator?
3. **Complex analysis needed** - Statistical interpretation
4. **Context matters** - "What does this mean for our operations?"
5. **Domain expertise helps** - Supply chain knowledge, fraud patterns
6. **Decision support needed** - "What should we do?"

### ❌ AI NOT NEEDED WHEN:
1. **Single obvious cause** - Asset is in wrong location
2. **Action is clear** - Reorder supplies
3. **No context needed** - Location mismatch is the problem
4. **No decision required** - Already know what to do
5. **Speed is critical** - Asset theft, reorder urgency
6. **Cost/benefit unfavorable** - Simple action doesn't justify AI cost

## Key Takeaways

### The 4 Anomaly Types
1. **Quantity Anomaly** - "Why so much?" → AI explains ✅
2. **Frequency Anomaly** - "Why so often?" → AI explains ✅
3. **Untracked Transfer** - "Where is it?" → Fix immediately ❌
4. **Low Stock Alert** - "Run out?" → Reorder now ❌

### AI Usage Philosophy
**Use AI strategically:**
- ✅ For complex situations requiring analysis
- ❌ Not for obvious problems requiring action
- 💡 Balance insight value vs. processing cost/time

### Investigation Priority
1. 🔴 **IMMEDIATE:** Untracked Transfer (Asset loss)
2. 🟠 **24 hours:** Quantity Anomaly (Potential fraud)
3. 🟠 **24 hours:** Frequency Anomaly (Potential fraud)
4. 🟡 **Business day:** Low Stock Alert (Procurement)

## Questions & Answers

**Q: Why doesn't Untracked Transfer have AI explanation?**  
A: The problem is obvious (asset in wrong place). AI would only waste 2-5 seconds saying "Yes, it's in the wrong place." Action is already clear: verify or recover.

**Q: What if Low Stock is critical (1 unit left)?**  
A: Priority escalates but AI still not needed. Immediate action: Emergency reorder. No analysis required.

**Q: Can I regenerate Quantity Anomaly explanation?**  
A: Yes! Click "Regenerate Explanation" in the modal. Groq will provide updated analysis.

**Q: What if Groq API fails?**  
A: Status shows "failed". Try regenerating. Check backend logs. Verify API key in `.env`.

**Q: How sensitive are the thresholds?**  
A: Current Z-score threshold = 2. This flags top 5% of unusual values. Adjustable in code if needed.

**Q: Can requester frequency anomalies become Quantity anomalies?**  
A: No, they're independent. Frequency anomaly = requests too often. Quantity anomaly = single request too large.
